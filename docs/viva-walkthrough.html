01 The problem you are solving 45s

Open here. Never open with the tech stack — open with why the thing exists.

Say "FinPilot is double-entry accounting software for Indian small businesses. The hard part isn't the screens — it's that accounting software is unforgiving. A rupee that rounds wrong, a journal entry that doesn't balance, or an invoice number with a gap in it is not a bug you patch later: it's a legal problem under GST. So I built the correctness rules into the schema and the database, not into the UI."
If asked "why not just use Tally?" Tally is desktop-first and single-company. FinPilot is multi-tenant and multi-company from the data model up — one accountant can hold the books of many businesses, which is the CA-firm case.

02 The rules the code cannot break 90s

This is your strongest section. Lead with it — it shows engineering judgement, not just CRUD.

Say "Before any code, I wrote ten invariants. They live in CLAUDE.md and every one of them is enforced in more than one layer, because any single layer eventually gets bypassed."

Explain these four — don't recite all ten:

RuleHow it's enforced
I1 — Money is an integer number of paise No floats, no Decimal128. Every money field name ends in Paise. Formatting happens once, at the React boundary.
I2 — Every journal entry balances sum(debit) === sum(credit), checked in a Mongoose pre('validate') hook, re-asserted inside the transaction before commit, and again by a nightly job. Three layers.
I3 — One writer to the ledger Only GeneralLedger.post() writes to journalentries. The invoice module doesn't know how to debit a receivable — it asks the ledger to.
I4 — Postings are append-only There is no PATCH /journal-entries/:id. A mistake is fixed by posting a reversing entry that references the original.
The line to land "Why paise and not decimals? Because floating point can't represent 0.1 exactly. JavaScript's safe integer range covers about ₹90 trillion in paise, which is six orders of magnitude more than any SME needs — so integers cost me nothing and remove a whole class of bug."

03 Architecture 60s

Say "It's a pnpm monorepo: apps/api, apps/web, and packages/shared which holds the Zod schemas so the client and server validate against the exact same definitions — they can't drift."

One codebase, three processes, selected by PROCESS_TYPE:

  • api — the HTTP server
  • worker — BullMQ consumers, scheduled jobs, the outbox publisher
  • ws — realtime (reserved)
Say "They're separate processes on purpose. The API must never consume a queue — a slow report export would otherwise block someone trying to raise an invoice."
Show apps/api/src/index.ts — the switch (env.PROCESS_TYPE).

04 The server refuses to boot 45s

A small section that always impresses, because most student projects crash at runtime instead.

Say "Two things are checked before the server will serve a single request. First, every environment variable is parsed through Zod — a missing JWT secret throws at boot with a readable message, because a server that starts without one is worse than a server that won't start."
Say "Second, MongoDB must be a replica set. I check hello.setName at connect time and disconnect if it's missing. A standalone MongoDB can't open a session, so every ledger transaction would fail at runtime — I'd rather fail at boot with an explanation."
Show config/env.ts and config/db.ts, then the boot log: 
mongo connected (replica set OK)  replicaSet: atlas-…-shard-0
api listening  port: 4100

05 Organization → Company → User 2 min

The most likely thing you'll be questioned on. Draw it on the board.

Organization  (plan, limits.maxCompanies: 10)
   ├── Company A ──┐
   ├── Company B ──┼── Membership(user, company, role) ──> User
   └── Company C ──┘      status: invited | active | suspended
EntityWhat it is
OrganizationThe billing and quota boundary — plan, limits, owner. Subscriptions hang off this, never off a company.
CompanyThe books boundary — GSTIN, state code, financial year. Every ledger row belongs to one.
UserPure identity — email, password hash, 2FA. Belongs to no company directly.
MembershipThe only thing that joins them: user + company + role.
RoleOrg-scoped, carries the permission array that gates every endpoint.
The line to land "A user joins a company, not an organization — and gets a different role in each. That's why one person can be the owner of their own business and an accountant in a client's books at the same time. That's the CA-firm case, and it's why Membership is a separate collection instead of a companyId field on the user."

Two ways to get a second company — know both:

  • Create: POST /companies → finds or creates your org → checks maxCompanies → creates the company → creates your owner Membership → seeds the chart of accounts. That last step isn't optional: a company with no accounts can't take a bank account, an invoice or a bill.
  • Join: invite by email → Membership{status:'invited'} + a 7-day signed token → the invitee must log in as that email to accept. A forwarded link grants nothing.

06 Tenant isolation 75s

Say "Multi-tenancy is where this kind of app leaks data. I refused to enforce it in the controllers, because enforcement that depends on every developer remembering a where clause fails the first time someone forgets."

How a request is scoped, in order:

  1. Client sends X-Company-Id on every request.
  2. tenantResolve looks for an active Membership for that user and company — no membership, no access.
  3. The resolved companyId goes into AsyncLocalStorage.
  4. A Mongoose plugin injects it into every find, updateOne and aggregate.
  5. A query with no resolved companyId throws.
The line to land "So there is no code path where forgetting a filter leaks another tenant's data — the query layer won't run without a tenant. And companyId is the first field of every compound index, so isolation is also what makes it fast."

07 Authentication & security 60s

  • argon2id for passwords, at the OWASP-recommended memory cost — not bcrypt, not SHA.
  • Short-lived access token + refresh token. Tokens never touch localStorage.
  • TOTP 2FA, with the secret encrypted at rest with AES-256-GCM.
  • Rate limiting in three tiers, with a deliberate asymmetry.
The line to land (this one is a real design decision) "The general limiter fails open — if Redis dies, people keep working. But the login limiter fails closed — if Redis dies, logins are refused. Unlimited credential stuffing is worse than an outage. Same component, opposite failure mode, chosen per risk."

08 The ledger — the core 2 min

Say "Everything financial ends up as a balanced journal entry. An invoice isn't stored as a total — it's stored as a document that causes a posting."

Issuing a ₹1,000 invoice at 18% GST posts, in one transaction:

Dr  Accounts Receivable      118000 paise
    Cr  Sales Revenue                100000 paise
    Cr  Output CGST                    9000 paise
    Cr  Output SGST                    9000 paise
Say "Debits equal credits or the transaction aborts. And because this is a replica set, the invoice, the journal entry and the document number are committed atomically — you can never end up with an invoice that has no posting."
If asked "why MongoDB for accounting? Isn't SQL better here?" Be honest and specific: "A relational database would also be a reasonable choice. What accounting needs is transactions, and MongoDB gives me those on a replica set — which is exactly why the replica set is mandatory rather than optional in my setup. What I gain is that an invoice with its line items is one document, so reading one is one query instead of a join."

09 Gapless numbering & idempotency 75s

Say "GST law requires invoice numbers to be gapless and sequential per company, per financial year. So I never count documents and add one — that races under load. Numbers come from an atomic findOneAndUpdate with $inc on a counters document, inside the same transaction that creates the invoice. If the transaction aborts, the number is never consumed."
Say "And every mutating endpoint takes an Idempotency-Key. If the user's network drops and the app retries, the stored response is replayed instead of raising a second invoice. The same key with a different body is rejected outright — that's a bug on the client, not a retry."
If asked "what if two users invoice at the same instant?" They serialize on the counter document. One gets 00021, the other 00022. Neither gets a duplicate, and no number is skipped.

10 Sales flow 90s · demo

Switch to the browser here. Talk while clicking.

  1. Parties — create a customer with GSTIN and state.
  2. Invoice draft — add lines; the server computes every total.
  3. Issue — assigns the gapless number and posts the journal entry.
  4. Payment — allocates against the invoice, posts another entry.
The line to land "The client may propose quantity, rate and discount. It may never propose a total. If the browser sends totalPaise, the server discards it silently and recomputes. Otherwise anyone with dev-tools could invoice ₹1,00,000 and book ₹1."
On GST "Intra-state splits into CGST + SGST; inter-state is IGST. That's decided by comparing the company's state code with the place of supply — which is why state is a validated dropdown and not a free-text box."

11 Purchases 45s

Bills (supplier invoices) and expenses. Same discipline, mirrored: a bill credits Accounts Payable and debits the expense account plus input GST.

Say "Input GST matters because it becomes input tax credit — what you can set off against the GST you collected. That's the link to the IMS section coming up."

12 Banking & reconciliation 60s

  • Register bank accounts, each mapped to a ledger account in the chart of accounts.
  • Import a statement as CSV with column mapping.
  • Each line gets a fingerprint so re-importing the same statement doesn't double-count.
  • Match statement lines against payments; status moves unreconciled → reconciled.
The line to land "The fingerprint is the interesting bit. People re-upload the same statement constantly. Without a deterministic fingerprint per line you silently double your bank balance."

13 GST & IMS 90s

GST returns working — GSTR-1 (outward supplies) and GSTR-3B (summary) are generated from the ledger, not from a separate tally, with a trace back to the journal entries that produced each figure.

Say "Generating the return from the ledger is the whole point. If the return and the books can disagree, one of them is lying — and you won't find out until a notice arrives."

IMS — Invoice Management System: the GSTN inbox of invoices your suppliers filed against your GSTIN. You accept, reject, or keep them pending; that decides your input tax credit. FinPilot matches each against your own bills and flags matched / amount_mismatch / not_in_books.

Say this before you're asked "The full IMS loop is implemented — sync, match, action, deadline alarm for credit at risk. It's currently wired to a mock GSP client that returns an empty list, because a real GSP connection needs a commercial licence. Swapping in a real client is one file; the interface is already defined."

14 Reports 60s

Trial balance, Profit & Loss, Balance sheet, Cash flow, Aged receivables, Aged payables — all computed from the ledger, all as-of a date.

Say "Trial balance is the honesty check: total debits must equal total credits across every account. If that ever doesn't hold, something bypassed the ledger — so I run it as a nightly reconciliation job, not just as a screen."
On CSV export "Export doesn't run inline. It creates a job, returns a job id, and a worker produces the file — because a large export shouldn't hold an HTTP connection open or block the API process."

15 AI Copilot 2 min

The part they'll be most curious about — and where you can show the most judgement.

Say "The Copilot is a tool-calling agent over Gemini. It has read tools for revenue, P&L, trial balance, balance sheet, cash position, invoices, bills, journal entries, bank transactions, parties, GST returns and the company profile. Every tool runs through the tenant plugin, so a tool is physically incapable of reading another company's data — even if the model asked it to."

Then the two rules that matter:

RuleWhy
I9 — never state a number it didn't retrieve Every figure in a reply is validated against the tool results from that same turn. If a number appears that isn't in a tool result, the answer is rejected and retried — then falls back to showing the raw data.
I10 — the AI proposes, a human confirms Write tools return a proposal. The AI can draft an invoice; it can never issue one.
The line to land "An accounting assistant that hallucinates a number is worse than no assistant, because it's confident and wrong. So I made grounding a validation step, not a prompt instruction — prompts are requests, validation is a guarantee."
If asked "what stops prompt injection?" Two things. The system prompt declares tool results to be data, never instructions. And more importantly, executeTool overwrites any companyId the model supplies with the server's own. Even a perfectly injected prompt cannot reach another tenant.

16 Admin console 75s

Say "There's one super admin for the whole platform. It's a single boolean with no tiers, and it can't be granted through any API — only by a script run on the server. The admin holds no company membership at all, so it has no tenant footprint."

What it can do, and the controls on each:

  • Sections — switch features off per company (Sales, GST, Copilot…). Enforced by the API returning 403, not by hiding a menu item. Chart of accounts and journal can never be switched off.
  • Impersonation — enter a customer's account to reproduce a bug. Requires a written reason, lasts 15 minutes, shows a permanent banner, and every request is tagged in the audit trail.
  • Dead-letter queue — inspect and replay failed background jobs.
The line to land "Support needs to see what the customer sees. The honest way to build that is a logged, time-boxed, reason-required session — not a backdoor and not asking people for their password."

17 Reliability & operations 45s

  • Health endpoint reporting per-component status, so a degraded dependency is visible rather than guessed at.
  • Transactional outbox — side effects are written in the same transaction as the data and published by a change stream, with a reaper as the fallback if the resume token is lost.
  • Prometheus metrics, structured logging, optional Sentry.
  • Dead-letter queue so a failed job is inspectable and replayable, never silently lost.
Say "The health check reports degraded, not just up or down. Right now Mongo is connected and Redis isn't reachable from my laptop — and the app keeps working, because the limiters fall back to an in-memory store. Partial failure is a state worth naming."

19 Live demo — the click-path 4 min

Rehearse this exact order. Don't explore live.

  1. Log in. Point out the token is held in memory, not localStorage.
  2. Switch company. Show the switcher listing several companies with your role in each — this is the multi-tenancy story in one click.
  3. Dashboard. Numbers come from the ledger, not a cache.
  4. Raise an invoice. Customer → line → issue. Point at the generated number.
  5. Open the journal. Show the entry that invoice just posted, and that debits equal credits. This is the moment that proves it's real accounting.
  6. Trial balance. Totals match.
  7. Copilot. Ask "what is my revenue" — it calls the tool and answers with the retrieved figure. Then ask about invoices.
  8. Admin console. Platform-wide view, Sections, and the audit trail.
Safety net Have the journal entry screen open in a second tab before you start. If the network misbehaves during the demo, that screen alone carries the argument.

20 Questions you should expect prep

QuestionAnswer
"Why integers for money?" Floats can't represent 0.1 exactly; errors compound over thousands of rows. Integer paise is exact, and the safe range covers ~₹90 trillion.
"Why must MongoDB be a replica set?" Transactions and change streams need one. A standalone can't start a session, so every ledger posting would fail — so I check it at boot and refuse to serve.
"How do you stop one tenant reading another's data?" Not in controllers. A Mongoose plugin injects companyId from AsyncLocalStorage into every query, and a query without one throws.
"What if the AI gets a number wrong?" It's validated, not trusted. Figures are checked against that turn's tool results; a failure retries, then falls back to raw data.
"Can the AI change my books?" No. Write tools return proposals. Nothing is posted without a human confirming.
"How do you correct a posted entry?" You don't edit it — postings are append-only. You post a reversing entry that references the original, which is what an audit trail requires.
"What happens if Redis goes down?" General limits fail open so work continues; login limits fail closed so credentials can't be brute-forced. Background jobs queue until it returns.
"Is it production-ready?" Be straight: the accounting core is. The GSP integration and the AI confirm-inbox are not finished, and I'd want load testing before real customers.
